CHAPTER II

REVIEW OF RELATED LITERATURE AND STUDIES

This chapter reviews multi-tenant software architecture, database Row-Level Security (RLS), Role-Based Access Control (RBAC), cryptographic credential verification, physical access control barriers, digital payment gateways, statutory tax automation, and international cybersecurity standards as the foundational pillars of KSYN FitConnect. It integrates theoretical literature and empirical studies by theme, followed by a synthesis of reviewed works, the identification of the research gap, and the conceptual framework operationalized through the Input–Process–Output (IPO) model.

Secure Multi-Tenant Franchise and Multi-Branch Management Systems

Multi-tenant architecture enables multiple independent organizational units or commercial franchisees to share a common application instance and database infrastructure while retaining complete logical isolation over their configurations, operational workflows, and private data. Bezemer and Zaidman (2010) identify infrastructure optimization, centralized version maintenance, and scalable resource pooling as primary advantages of multi-tenancy, while emphasizing that software architectural complexity can offset these benefits if tenant boundaries are poorly engineered. The National Institute of Standards and Technology (NIST) cloud computing reference architecture reinforces resource pooling as a core cloud characteristic; however, a shared web application does not automatically ensure tenant data security without programmatic isolation boundaries (Bezemer & Zaidman, 2010; Mell & Grance, 2011).

An industrial experience report by Bezemer et al. (2010) investigates the reengineering of legacy single-tenant enterprise applications into shared multi-tenant deployments, identifying database query isolation and transaction scoping as the most critical failure points. In complementary research, Krebs et al. (2012) analyze architectural trade-offs between shared-database and separate-database patterns, demonstrating that while shared-database multi-tenancy minimizes hosting costs, it introduces severe cross-tenant data leakage risks if tenant identifiers are not enforced systematically across all query pathways. Neither investigation directly addresses the unique operational characteristics of fitness franchises, where cross-branch access privileges, coach commission splits, front-desk locker rentals, and physical turnstile barriers operate simultaneously (Bezemer et al., 2010; Krebs et al., 2012).

Contemporary guidance from the OWASP Foundation extends multi-tenant security perimeters beyond basic SQL queries to encompass memory caches, asynchronous workers, background reporting tasks, and file exports (OWASP Foundation, 2023). In multi-branch franchise platforms, centralized corporate oversight must coexist with branch confidentiality: corporate administrators require consolidated financial visibility to compute franchise royalties, while individual branch managers and cashiers must be strictly prohibited from viewing or altering adjacent branch records. For KSYN FitConnect, each franchise branch operates as an isolated tenant. Membership registrations, subscriptions, locker reservations, inventory sales, and shift audits execute within strictly partitioned branch scopes, while corporate reporting uses authorized query paths rather than unrestricted database access.

Tenant Data Isolation and Database Row-Level Security (RLS)

Tenant data isolation ensures that authenticated users are programmatically restricted from accessing or manipulating records outside their authorized organizational boundary. Krebs et al. (2012) establish the architectural imperative of tenant separation, while OWASP categorizes Broken Object-Level Authorization (BOLA) and Insecure Direct Object Reference (IDOR) as the leading web and API security vulnerabilities (OWASP Foundation, 2023). In a vulnerable multi-tenant system, simply substituting a primary key identifier in an API request allows an authenticated attacker to view or delete another branch's member profiles or revenue ledgers.

PostgreSQL Row-Level Security (RLS) provides a native, kernel-level enforcement mechanism that evaluates row-visibility and modification policies directly within the database engine (PostgreSQL Global Development Group, 2023). When RLS is enabled on a table, the database suppresses rows failing the security policy by default. However, standard administrative connections and database superusers can bypass these policies unless strict database role configuration and FORCE ROW LEVEL SECURITY directives are applied. Database privileges must therefore be configured alongside application-level middleware to establish defense in depth.

In KSYN FitConnect, every tenant-owned table incorporates a mandatory branch_id foreign key. To prevent context bleeding across pooled database connections, the application server establishes transaction-local tenant context using the session variable: SET LOCAL app.current_tenant_id = :authenticated_branch_id; Within that transaction block, PostgreSQL RLS policies evaluate table rows against this setting. If an application bug omits a WHERE branch_id = ... clause, PostgreSQL automatically suppresses all rows belonging to other branches, failing closed by default. Parameterized queries eliminate SQL injection vulnerabilities, input validation guards API boundaries, and immutable audit logs record the actor, tenant context, target resource, and outcome on every state change (OWASP Foundation, 2020, 2023).

Role-Based Access Control and Least-Privilege Authorization

Role-Based Access Control (RBAC) associates fine-grained permissions with defined organizational roles and assigns users to those roles based on their operational responsibilities (Ferraiolo & Kuhn, 1992; Sandhu et al., 1996). Ferraiolo and Kuhn formalize RBAC principles, while Sandhu et al. describe hierarchical access models that prevent users from acquiring permissions exceeding their legitimate functional scope. These models support organizing authority around business responsibilities rather than managing ad-hoc user permissions individually.

The Principle of Least Privilege (PoLP) mandates that each user account receives only the minimum system access necessary to perform authorized duties. However, in a multi-branch franchise, role assignment alone is insufficient: two users possessing the "Branch Administrator" role must not access each other's branch facilities. Fine-grained authorization must therefore bind role permissions to explicit tenant scopes and record ownership relationships (OWASP Foundation, 2023). KSYN FitConnect enforces a seven-tier role hierarchy governing corporate leadership, branch investors, general managers, front-desk staff, personal trainers, and gym members.

Authentication, Session Management, and Credential Security

Authentication verifies an identity claim; session management maintains authenticated state across stateless HTTP requests; authorization enforces permissible operations. NIST Special Publication 800-63B-4 establishes modern guidelines for digital identity, authenticator assurance, and credential protection (Temoshok et al., 2025). KSYN FitConnect combines adaptive salted password hashing, brute-force rate limiting, cryptographically signed JSON Web Tokens (JWT), and server-side session invalidation.

RFC 7519 defines the JSON Web Token (JWT) structure, while RFC 8725 establishes best current practices to mitigate signature stripping, algorithm confusion, and replay attacks (Jones et al., 2015; Sheffer et al., 2020). KSYN FitConnect issues signed JWT tokens containing strictly non-confidential claims (user ID, role, and branch context). Tokens are validated using explicit cryptographic algorithms and restricted expiration windows. Attendance access tokens and administrative login tokens utilize distinct payload signatures and purpose validation rules.

For password protection, RFC 2898 and OWASP password storage standards mandate adaptive, salted one-way hashing functions (OWASP Foundation, 2023). KSYN FitConnect utilizes bcryptjs (Blowfish-based cipher) configured with an adaptive computational work factor of 10 and unique cryptographic salts per account. Passwords are never stored in plaintext, logged to disk, or exposed in API payloads. Browser sessions utilize HTTP-only, Secure cookies with SameSite=Strict attributes to eliminate Cross-Site Scripting (XSS) and Cross-Site Request Forgery (CSRF) vectors. Transport Layer Security (TLS 1.3) protects all network communications against interception (Rescorla, 2018).

Physical Turnstile Solenoid Relays and Contactless Verification

Commercial gym access control requires automated physical barrier actuation to enforce membership validity and prevent unauthorized entry. While Liew and Tan (2021) demonstrate a software-based QR attendance system in an educational setting, their model lacks physical hardware barriers, anti-passback cooldown logic, and commercial payment validation. In contrast, commercial fitness facilities require real-time hardware turnstile integration to prevent visual pass sharing and tailgating.

RFC 6238 defines the Time-Based One-Time Password (TOTP) algorithm, establishing that short-lived validity windows combined with atomic single-use nonce consumption eliminate token replay attacks (M'Raihi et al., 2011). KSYN FitConnect implements this principle for member access control: 1. Authenticated members generate dynamic HMAC-SHA256 optical QR passes that expire strictly after 60 seconds. 2. Upon presentation to a turnstile barcode reader or presentation of a 13.56MHz contactless RFID keycard UID, the server validates credential authenticity and executes an atomic database transaction. 3. The server immediately consumes the token nonce and verifies that the member is not subject to an active anti-passback cooldown (enforcing a mandatory 5-minute delay before re-entry). 4. Upon successful validation, the server dispatches an unlocking pulse command (SOLENOID_RELAY_OPEN, 500ms duration) over a local WebSocket bridge driver (turnstileBridge.js) to the physical turnstile solenoid relay.

Digital Payments and Statutory Fiscal Compliance in the Philippines

Commercial fitness franchise operations require integrated digital payment channels and statutory tax compliance. Traditional manual cash collections and paper receipts frequently result in untracked cash variances and delayed bank settlements. Modern fintech application programming interfaces (APIs) enable asynchronous payment collection across mobile wallets and credit rails.

KSYN FitConnect integrates the Xendit payment gateway API, providing members with real-time checkout options for Credit/Debit cards, GCash, Maya, and QR Ph. Webhook callback notifications verify asynchronous settlements using cryptographic HMAC signatures, ensuring that membership subscriptions are activated only upon guaranteed settlement. Furthermore, under Philippine tax law (National Internal Revenue Code / Republic Act No. 8424) and Bureau of Internal Revenue (BIR) Revenue Regulations, independent fitness coaches and contracted service providers are subject to a 10% Creditable Withholding Tax (CWT). The platform automates this deduction at the point of session verification, logging gross earnings, tax withheld, and net payouts, thereby generating BIR Form 2307 audit ledgers while calculating fixed 7.5% corporate franchise royalties on gross branch revenues.

Data Privacy, Intellectual Property, and Information Security Standards

Republic Act No. 10173, the Data Privacy Act of 2012, mandates that personal information controllers implement organizational, physical, and technical measures to protect personal data against accidental or unlawful destruction, alteration, and unauthorized disclosure (National Privacy Commission, 2016a). Public front-desk logbooks that expose member names, phone numbers, and check-in times violate privacy proportionality principles. KSYN FitConnect replaces paper logbooks with encrypted digital records, restricts profile access via RBAC, and sanitizes audit logs to exclude confidential health details.

Pursuant to Republic Act No. 8293 (Intellectual Property Code of the Philippines), software source code, system architectures, cryptographic QR generation algorithms, and multi-tenant RLS schemas remain the exclusive intellectual property of the student development authors, licensed to KSYN Fitness Inc. for operational deployment and academic evaluation.

For technical security evaluation, the study adopts the international standard ISO/IEC 27001:2022 (Information Security, Cybersecurity and Privacy Protection — Information Security Management Systems) and its companion standard ISO/IEC 27002:2022 (Information Security Controls). ISO/IEC 27001:2022 provides an internationally recognized framework of 93 information security controls organized into four core themes: 1. Organizational Controls (Clause 5): Policies for access control (5.15), access rights (5.18), and privacy protection (5.34). 2. People Controls (Clause 6): Information security responsibilities (6.5) and access revocation upon termination. 3. Physical Controls (Clause 7): Physical entry controls and barrier actuation (7.2). 4. Technological Controls (Clause 8): Secure authentication (8.5), vulnerability management (8.8), audit logging (8.15), network security (8.20), use of cryptography (8.24), and application security requirements (8.26).

The OWASP Application Security Verification Standard (ASVS v5.0) and Web Security Testing Guide (WSTG v4.2) complement ISO/IEC 27001:2022 by providing granular verification requirements for testing cross-tenant isolation, parameter tampering, and token replay resistance (OWASP Foundation, 2020, 2025).

Synthesis of Literature and Studies

The reviewed literature establishes that centralized multi-tenant cloud platforms deliver significant operational efficiencies for franchise networks, provided that tenant boundaries are enforced at the database level rather than through interface filters alone (Bezemer et al., 2010; Krebs et al., 2012). Research by Ferraiolo and Kuhn (1992) and Sandhu et al. (1996) demonstrates that Role-Based Access Control effectively organizes operational responsibilities, while OWASP guidance establishes that multi-tenant security requires binding roles to verified tenant scopes to prevent BOLA and IDOR vulnerabilities.

Security engineering literature demonstrates that salted adaptive password hashing (bcrypt RFC 2898), time-bounded dynamic HMAC tokens (RFC 6238), and TLS 1.3 transport encryption form a robust defense-in-depth model for web applications. Furthermore, physical access control research indicates that combining dynamic optical passes with hardware solenoid relay drivers and anti-passback cooldown rules resolves the pass-sharing and congestion vulnerabilities inherent in manual paper logbooks. Statutory Philippine frameworks—including RA 10173 for data privacy, RA 8293 for software intellectual property, and BIR Form 2307 regulations for tax withholding—establish the legal context governing commercial gym management.

Within the reviewed literature, the explicit research gap is the unified engineering and empirical evaluation of these disparate mechanisms—multi-tenant database Row-Level Security, a seven-tier franchise role hierarchy, Xendit payment gateways, automated 7.5% corporate royalties, 10% BIR 2307 tax deductions, front-desk locker deposit accounting, and WebSocket turnstile solenoid relay actuation—within a commercial fitness franchise evaluated against ISO/IEC 27001:2022 Annex A security controls. KSYN FitConnect directly bridges this gap.
