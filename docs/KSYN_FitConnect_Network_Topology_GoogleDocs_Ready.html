3.3.X Enterprise Network Architecture and Topology Overview

To support the multi-branch commercial fitness franchise operations detailed in Chapters I and II, KSYN FitConnect implements a centralized, cloud-interconnected network topology. The infrastructure connects corporate headquarters with the franchise branch facilities distributed across metropolitan commercial centers, including the modeled nodes: BGC Flagship (BGC-01), Alphaland Makati (MKT-02), Fairview Pontiac (FRV-03), Kapitolyo Pasig (KAP-04), Del Monte Quezon City (DLM-05), Alabang (ALB-06), and Katipunan Regis Center (KTP-07). The network architecture is structured as a hierarchical Hub-and-Spoke enterprise Wide Area Network (WAN) centered upon an elastic cloud infrastructure backbone.

As illustrated in Figure 3.X, the system utilizes a high-availability cloud WAN backbone designated as AWS Cloud. This central cloud routing core interconnects the primary Corporate Headquarters / Central Server node (top cluster) with three major regional franchise branch routing zones (Zone A, Zone B, and Zone C). This architecture satisfies the primary research objectives of Chapter I by providing high-throughput transactional processing, continuous mobile client connectivity, and multi-tenant data synchronization while strictly maintaining tenant data boundaries.

3.3.X.1 Central Cloud Backbone and Server Infrastructure

The core of the enterprise topology is anchored by the AWS Cloud backbone. In the production deployment specification of KSYN FitConnect, the application backend and relational data store are hosted within a high-performance cloud container infrastructure environment (compatible with AWS Cloud and container PaaS platforms such as Render.com within the Singapore ap-southeast-1 availability zone for minimal latency to Philippine internet service providers). The central cloud server (modeled as Server-PT SERVER behind Cisco 2960-24TT Switch14 and gateway router Cisco 2811 R0) executes the following essential platform services:

  • Unified Application and API Gateway: Hosts the production React 18 client single-page application (SPA), Node.js Express RESTful API controllers, and WebSocket real-time communication daemons on a unified container port, eliminating Cross-Origin Resource Sharing (CORS) overhead.
  • Multi-Tenant PostgreSQL Relational Engine: Manages persistent records across all franchise branches using PostgreSQL Row-Level Security (RLS). Every query execution injects the tenant session variable SET LOCAL app.current_tenant_id = [branch_id], ensuring mathematical row isolation at the database kernel level.
  • Automated Franchise Financial Engine: Computes the mandatory 7.5% corporate franchisor royalty cut on gross branch receipts and generates Philippine Bureau of Internal Revenue (BIR) Form 2307 Creditable Withholding Tax schedules.
  • Cryptographic Verification Daemon: Validates incoming 60-second dynamic HMAC-SHA256 member passes and manages the in-memory anti-replay nonce cache to prevent duplicate entry attempts.

3.3.X.2 Regional Franchise Branch Clusters and Local Edge Nodes

The enterprise network partitions the modeled franchise branches into distinct routing and distribution zones, each fronted by dedicated edge routers and switching fabrics:

1. Regional Branch Cluster A (South and Central Metro Sector)

Terminated by gateway router Cisco 2811 R1 and distribution switch 2960-24TT Switch0, this cluster represents high-density commercial facilities such as BGC Flagship and Alabang Prime. The distribution layer fans out to dedicated access switches (Switch4, Switch3, and Switch2). Connected to these edge switches are front-desk cashier POS terminals (PC-PT), dedicated hardware Cisco 7960 IP Phones for inter-branch and HQ operational voice communication, and high-gain Wireless Access Points (AccessPoint-PT). The access points deliver continuous wireless coverage across the gym floor, enabling athletes to load their digital dynamic passes and coaches to record periodization splits.

2. Regional Branch Cluster B (East and North Metro Sector)

Terminated by gateway router Cisco 2811 Router0 and access switches Switch16 and Switch17, this zone represents modeled facilities such as Del Monte Quezon City and Fairview Pontiac. It supports administrative management workstations (PC-PT and Laptop-PT) utilized by Branch Administrators (General Managers) to perform daily cashier shift audits, review locker agreements, and execute the Two-Stage Branch Transfer Clearance Protocol. Hardware Cisco 7960 IP Phones and wireless access points provide dedicated local operational support.

3. Regional Branch Cluster C (Commercial Core and Regional Sector)

Terminated by gateway router Cisco 2811 R2 and distribution switch Switch1, this cluster routes traffic across floor switches Switch10, Switch9, and Switch8, serving modeled hubs such as Alphaland Makati, Kapitolyo Pasig, and Katipunan Regis Center. Front-desk workstations run optical camera check-in verifiers and cashier checkout interfaces, supported by local wireless APs and voice telephony.

3.3.X.3 Operational Alignment with Manuscript Chapters I–III

The depicted network topology directly operationalizes the research parameters specified across Chapters I to III:

  • Software-Delimited Access Verification: Consistent with Chapter I's delimitation of physical turnstile relays and Arduino/ESP32 microcontrollers, entry validation is conducted via web camera optical scanners connected to front-desk workstations (PC-PT). Members connect their mobile devices to the local AccessPoint-PT, generate an ephemeral 60-second dynamic QR code pass signed via HMAC-SHA256, and present it to the optical scanner. The workstation transmits the token across the AWS Cloud backbone to Server-PT SERVER for sub-20-millisecond verification.
  • Tenant Data Isolation over Shared Cloud Infrastructure: While all regional routers (R1, Router0, R2) route traffic to the same central database server via the cloud backbone, multi-tenant row isolation is enforced at the database level. Queries originating from a workstation at Branch A cannot return records belonging to Branch B, fully neutralizing Broken Object-Level Authorization (BOLA) and Insecure Direct Object References (IDOR).
  • Front-Desk Shift Governance and Blind Drawer Close: Workstations at the branch access switches operate the Point of Sale (POS) cashiering interface. Cashiers open shifts with an opening float, process walk-in passes and retail items, and submit blind drawer closing counts. The server calculates shortages or overages automatically without exposing expected figures beforehand, ensuring strict cash governance.
  • Data Privacy Act of 2012 (RA 10173) Compliance: Network transmissions across the AWS Cloud WAN backbone utilize Transport Layer Security (TLS 1.3). Front-desk terminal interfaces feature active Personally Identifiable Information (PII) masking (e.g., +63 917 **** 892) to prevent visual shoulder-surfing in public gym reception areas.
