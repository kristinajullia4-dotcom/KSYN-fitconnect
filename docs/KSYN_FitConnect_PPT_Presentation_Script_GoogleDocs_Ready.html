SLIDE 3: Chapter I — Introduction, Background & Proposed Solution
Visual: Fragmented workflow vs. KSYN FitConnect centralized platform diagram.
[Speaker 1: Luis Gabriel Bautista]

"KSYN Fitness Gym is expanding from a single-facility gym into a distributed franchise network across Metro Manila. However, rapid commercial growth has exposed critical operational bottlenecks.

"Currently, corporate leadership and independent franchise branch operators rely on disconnected spreadsheets, physical paper receipts, and unencrypted messaging applications.

"This creates three acute operational risks: First, attendance bottlenecks and static pass sharing. Second, manual, error-prone royalty calculations where branch managers must physically compile sales for corporate remittances. And third, the multi-tenant security hazard: in an improperly architected system, one branch operator could accidentally or maliciously access confidential revenue and member data belonging to another franchisee.

"To solve this, we engineered KSYN FitConnect—a multi-tenant web application featuring strict server-side Role-Based Access Control and database-level tenant isolation, empowering corporate oversight while preserving branch confidentiality."

Visual: General objective and four specific objectives mapped to Design, Develop, Test, Evaluate.
[Speaker 2: Merynelle B. Bozar]

"Our General Objective is to design, develop, test, and evaluate KSYN FitConnect as a secure multi-tenant franchise management system with Role-Based Access Control and tenant data isolation.

SLIDE 7: Chapter II — Multi-Tenant Systems & Tenant Data Isolation
Visual: Shared Database / Shared Schema architectural diagram with PostgreSQL RLS filtering.
[Speaker 2: Merynelle B. Bozar]

"In enterprise literature, multi-tenancy is realized through three patterns: separate databases, shared database with separate schemas, or shared database with shared schema.

"KSYN FitConnect adopts the Shared Database, Shared Schema with Row-Level Security paradigm. This maximizes hardware resource utilization while eliminating database management overhead.

"To eliminate Broken Object-Level Authorization (BOLA) and IDOR vulnerabilities, we do not rely solely on application-layer 'WHERE branch_id' clauses. Instead, we mandate PostgreSQL Row-Level Security (RLS). Before any query executes, the application establishes a local transactional session variable: 'SET LOCAL app.current_tenant_id = [branch_id]'. The database kernel itself enforces row filtering, guaranteeing that even a compromised API endpoint cannot retrieve records from another franchise branch."

SLIDE 8: Chapter II — Access Control & Secure Development
Visual: RBAC role hierarchy, Argon2id hashing flow, and JWT claim structure.
[Speaker 3: Jullia Krisitina C. Marquez]

"Access control in KSYN FitConnect enforces the principle of least privilege across six distinct roles: Corporate Admin, Branch General Manager, Front-Desk Cashier, Coach, Member, and Franchise Inquirer.

"For credential security, passwords are encrypted using Argon2id—the winner of the Password Hashing Competition—offering proven resistance against GPU-accelerated brute force and side-channel attacks.

"Authenticated sessions are secured using cryptographically signed JSON Web Tokens (JWTs) containing signed tenant identifiers and role claims, complemented by HTTPS transmission and CSRF protection."

SLIDE 9: Chapter II — Dynamic Pass Verification, Privacy & Standards
Visual: 60-second HMAC-SHA256 rotating QR pass timeline and ISO/IEC 25010 radar chart.
[Speaker 3: Jullia Krisitina C. Marquez]

"To address attendance fraud and screenshot sharing, we engineered dynamic time-expiring optical QR passes.

"The member's mobile device generates an HMAC-SHA256 signature containing a single-use cryptographic nonce and a Unix timestamp valid for exactly 60 seconds.

"When scanned at the counter, the server validates the signature, performs an atomic database consumption check to prevent replay attacks, and enforces a 15-minute Anti-Passback lockout to prevent members from passing their phone back to an unpaid guest outside.

"Furthermore, under Republic Act 10173 (Data Privacy Act of 2012), personal health and billing records are strictly compartmentalized: personal trainers can only access their assigned clients, while corporate administrators only view anonymized branch health metrics.

"Our evaluation framework adheres directly to the ISO/IEC 25010 software product quality model and OWASP ASVS guidelines."

If there is a discrepancy, the system flags the variance for manager PIN authorization, eliminating cashier skimming."

Section 4: Panel Defense Trap Anticipation & Technical Responses
Panelist Trap Question ❌ Dangerous / Failing Answer Winning Technical Defense
"Where is your physical RFID reader or ESP32 turnstile?" "We ran out of budget/time to purchase the wires and sensors." "Physical electromechanical turnstiles and microcontrollers were explicitly delimited in Chapter I. Our research focuses on Enterprise Software Architecture, PostgreSQL Row-Level Security, and Cryptographic Authentication. Front-desk optical camera scanning provides a scalable, zero-hardware failure solution accessible on standard cashier laptops."
"How do you know an attacker cannot bypass branch isolation with SQL injection?" "We put 'WHERE branch_id = ...' in all our backend queries." "We employ defense-in-depth: all queries use parameterized statements to prevent SQL injection, and data isolation is enforced at the database kernel level through PostgreSQL Row-Level Security (RLS) via 'SET LOCAL app.current_tenant_id = [branch_id]'. Even if an attacker injects a rogue query, the database engine will not return records outside the authorized tenant."
"Why is the franchisor royalty set to exactly 7.5%?" "We just picked 7.5% as an example number." "The 7.5% royalty rate is based directly on actual fitness franchise industry benchmarks gathered during our Chapter III stakeholder requirements analysis with KSYN leadership, combined with standard Philippine BIR Form 2307 (5% Expanded Withholding Tax) deduction rules."
"What stops a member from taking a screenshot of their QR code and sending it to a friend?" "We tell our cashiers to look at the member's face." "Our passes are dynamic and cryptographic. Using HMAC-SHA256, each QR pass is valid for only 60 seconds and contains a single-use nonce. A screenshot sent to a friend outside will expire before it reaches the counter. Furthermore, once scanned, our 15-minute Anti-Passback rule locks out that member ID from immediate re-use."
"Why did you use React and Node.js instead of PHP or standard HTML?" "It is just the stack we are most comfortable using." "React.js provides a responsive Single-Page Application (SPA) architecture required for continuous optical video feed processing at the counter. Node.js with Express and WebSockets handles asynchronous, non-blocking I/O, allowing instant live attendance broadcast from cashier scanners to management dashboards."
